# 2. Лексическая структура

Источники: `C/java/org/zenframework/z8/compiler/parser/grammar/lexer/Lexer.java`, `ABC.java`, `token/*`, `C/java/org/zenframework/z8/compiler/file/File.java`, `parser/expressions/Constant.java`.

## 2.1 Ввод и разделители

При чтении файлов `File.read()` декодирует байты как UTF-8 в Java `char[]`. Пробельные символы лексера — пробел и горизонтальная табуляция; переводы строки — CR и LF, CRLF обрабатывается совместно. Лексер пропускает пробелы, переводы строк и комментарии перед передачей токенов парсеру. Не следует считать произвольные Unicode-пробелы допустимыми разделителями.

Однострочный комментарий начинается `//` и продолжается до CR, LF или конца файла. Блочный комментарий `/* ... */` может содержать вложенные блочные комментарии; каждый вложенный `/*` должен закрываться своим `*/`. Незавершённый комментарий вызывает ошибку лексера. Последовательности внутри строковых литералов являются частью строки.

## 2.2 Идентификаторы

Идентификаторы чувствительны к регистру. `_` разрешён первым и последующими символами; цифры ASCII `0`–`9` разрешены после первого символа. Прочие допустимые символы вычисляются `ABC.isAlpha` и `Character.isJavaIdentifierPart(char)`, с исключением ASCII-пунктуации, цифр в начале и символов `\`, обратной кавычки, `$`, `#`, `@`. Реализация классифицирует отдельные UTF-16 `char`, а не гарантирует поддержку всех Unicode-кодовых точек. Кириллица используется в реальных BL-исходниках.

Разбор объявления дополнительно вызывает `Lexer.checkIdentifier` в некоторых контекстах: `native`, `void`, `int`, `abstract` отвергаются в проверяемых позициях имени переменной/поля/типа; при этом они лексически являются идентификаторами и `void`, `int` нужны как имена типов. Это ограничение нельзя обобщать на все контексты без дополнительной проверки.

## 2.3 Ключевые и зарезервированные слова

Ключевые токены: `operator`, `do`, `for`, `while`, `if`, `else`, `break`, `continue`, `return`, `this`, `super`, `container`, `null`, `import`, `class`, `public`, `protected`, `private`, `extends`, `enum`, `records`, `auto`, `new`, `static`, `try`, `catch`, `finally`, `throw`, `virtual`, `final`, `instanceof`. `true` и `false` — отдельные булевы константы.

Лексер специально отвергает зарезервированные имена: `boolean`, `byte`, `case`, `char`, `const`, `default`, `double`, `float`, `goto`, `implements`, `interface`, `long`, `package`, `short`, `strictfp`, `switch`, `synchronized`, `throws`, `transient`, `volatile`. Имена `bool`, `decimal`, `string`, `date`, `guid` и другие библиотечные имена типов не являются ключевыми токенами только из-за их роли типов.

## 2.4 Пунктуация и операции

Односимвольные: `~ & | ^ ( ) % * / + - , . ; ? [ ] { } ! = < > :`. Двухсимвольные: `!= == <= >= += -= *= /= %= &= |= ^= && || ?:`. `//` и `/*` начинают комментарии. Пробел между `?` и `:` меняет набор токенов: `?:` — отдельный токен. Токенов `++`, `--`, `<<`, `>>` в лексере нет; нельзя подменять операции BL правилами Java.

## 2.5 Числа

Целый литерал — десятичные цифры либо `0x`/`0X` и шестнадцатеричные цифры; значение разбирается `Long.parseLong`, то есть проверяется диапазон знакового Java `long`. Десятичный литерал содержит точку: например, `1.0`, `.5`, `1.`. После точки допускается показатель `e`/`E`, но его знак `+` или `-` обязателен, как и следующие цифры: `1.0e+2`. Отдельный показатель без точки числовым лексером не распознаётся как единый decimal. Тип — `int` или `decimal` соответственно.

Знаки `+`/`-` могут входить в числовой токен при определённом предыдущем токене (`isNumberSign`), с пробелами/табуляцией после знака. В других контекстах это операторы; не предполагается эквивалентность для предельных значений и всех позиций.

При лексическом разборе decimal хранится как `BigDecimal`, но это не означает сохранения всех его десятичных цифр при исполнении. `DecimalToken.format(true)` выдаёт `BigDecimal.toString()` без кавычек, а `Constant.getCode` вставляет результат как аргумент `new decimal(...)` в Java. Если этот текст Java трактует как литерал `double`, вызывается соответствующий конструктор `decimal(double)` и точность ограничивается промежуточным `double` до преобразования в `BigDecimal`. Для контрольного `0.12345678901234567890` проверено наличие аргумента без кавычек в сгенерированном Java; сам Java-код не компилировался. Вид и валидность конкретного сгенерированного Java-литерала зависят от формата значения. Источники: `token/DecimalToken.java`, `parser/expressions/Constant.java`, `S/org/zenframework/z8/server/types/decimal.java`.

## 2.6 Строки и ресурсы

Строка заключается в двойные кавычки, может содержать перевод строки. Лексер распознаёт `\b`, `\f`, `\n`, `\r`, `\t`, `\"`, `\\`, `\'`; другая escape-последовательность вызывает ошибку. Непечатаемые символы кроме явно допускаемых пробела, табуляции и переводов строк лексер пропускает. Тип литерала — `string`.

Если значение строки начинается и заканчивается `$` и содержит более двух символов, `Constant.isNLSString` трактует внутренний текст как ключ ресурса. При семантической проверке ищется запись для `ru`; отсутствие вызывает ошибку. Это не лексический токен `$`: доллар находится внутри строкового значения. Поведение локализации при исполнении зависит от системы ресурсов.

## 2.7 Одинарные кавычки

Одинарные кавычки ограничивают специальные константы, а не символьные или обычные строковые литералы. Лексер последовательно пытается распознать дату/время, GUID и двоичные данные.

| Тип | Форма и ограничения исследованного лексера |
|---|---|
| `date` | `'день/месяц/год'`, необязательно пробел и `час:минута:секунда`; год 1–9999, дата проверяется по календарю, часы 0–23, минуты и секунды 0–59; компоненты дня и месяца до двух цифр, года до четырёх |
| `datespan` | `'дни часы:минуты:секунды'`, неотрицательные дни, часы/минуты/секунды с теми же ограничениями |
| `guid` | `'xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx'`, шестнадцатеричные цифры без фигурных скобок |
| `binary` | `'n, n, ...'`, минимум один байт 0–255, числа десятичные или `0x`-шестнадцатеричные; между элементами допустимы пробельные символы и переводы строк |

Диагностическая строка лексера сообщает иной диапазон годов; фактическая проверка `getDateTime` использует 1–9999. Для ветви времени без даты `getDateTime` при успешном разборе создаёт `DateToken(new Date())`: `compiler.util.Date()` инициализирует `GregorianCalendar` текущим моментом, а `DateToken.format(true)` вставляет его миллисекунды в генерируемый Java-код. В этой ветви после чтения часа код дополнительно сдвигается на один символ перед чтением минут; компилятор принял контрольную форму `'12:34:56'` и сгенерировал для неё Java-конструктор даты с числом миллисекунд. Допустимость других форм нужно проверять на лексере. Это особенность текущей реализации, а не предполагаемая семантика литерала времени. Загрузка `compiler.util.Date` также вызывает `TimeZone.setDefault` с `Europe/Moscow` для JVM компилятора. Для дат с явно указанными компонентами `DateToken` также генерирует миллисекунды.
