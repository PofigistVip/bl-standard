# 9. Стандартные типы и библиотека

Источники: `L/org/zenframework/z8/lang/*.bl`, `L/org/zenframework/z8/lang/sql/*.bl`, `C/java/org/zenframework/z8/compiler/parser/type/members/ArrayMethods.java`, `S/org/zenframework/z8/server/types/`, `S/org/zenframework/z8/server/runtime/{RCollection,RLinkedHashMap}.java`. Машиночитаемый обзор деклараций и полный перечень файлов библиотеки — в [каталоге](11-library-catalog.md). Сигнатуры BL являются внешним интерфейсом компилятора; Java-метод, не объявленный в BL или не синтезированный компилятором, не становится доступным только потому, что существует в runtime.

## 9.1 Основные семейства

| BL-тип | Назначение и наблюдаемая связь |
|---|---|
| `void` | отсутствие возвращаемого значения |
| `primary` | базовое объявление семейства значений |
| `int` | целый тип, Java `org.zenframework.z8.server.types.integer`; хранит `long` |
| `decimal` | десятичное значение, Java `types.decimal`, на основе `BigDecimal`, с отдельным состоянием NaN |
| `bool` | логическое значение и перегрузки логических операций |
| `string` | строковое значение и операции над строками |
| `date`, `datespan` | дата/время и длительность; отдельные типы с операциями между ними |
| `guid`, `binary` | UUID и бинарная последовательность |
| `geometry`, `file`, `exception` | значение геометрии, файла и исключения, с API из соответствующих `.bl` |
| `Object` | корень объектных возможностей runtime, атрибуты и идентичность объектов |
| `Math`, `encoding`, `Attribute` | библиотечные объявления, а не ключевые слова |
| `sql_*` | объекты SQL-выражений, а не обычные скалярные значения; поддерживаемые операции определяются отдельными `.bl` и серверными типами |

`vector`, `bitset`, `sql_vector`, `sql_bitset` присутствуют в таблице имён компилятора, но соответствующие `.bl` в данном checkout не найдены. Таблица разрешения имён не доказывает наличия реализации.

## 9.2 Подтверждённые детали чисел

`integer` хранит знаковый Java `long`; обычные целочисленные операции `+ - * / %` делегируются соответствующим операциям `long`. Следовательно сложение и умножение выполняются с обычным для Java переполнением, а деление на ноль вызывает Java `ArithmeticException`; деление целых отбрасывает дробную часть к нулю. Операции с `decimal` делегируют десятичной реализации. Объявления BL `int.Min` и `int.Max` равны соответственно `-0x7fffffffffffffff` и `0x7fffffffffffffff`; это не доказательство запрета другого значения при вычислении.

`decimal` хранит `BigDecimal` и флаг NaN. `set(BigDecimal)` при точности более 38 уменьшает scale с `RoundingMode.CEILING`; операции создают результаты через `decimal`, поэтому эта обработка применяется и при создании результатов. Деление `decimal` использует вычисляемый `MathContext`; арифметическая ошибка в этой операции оборачивается в `RuntimeException`. Эти детали относятся к текущей Java-реализации, а не к абстрактной произвольной decimal-арифметике.

## 9.3 Синтезированные операции коллекции

Обозначим `T` тип элемента, `K` тип ключа. Это именно сигнатуры, которые добавляет компилятор через `ArrayMethods`; `T` может быть типом с оставшимися измерениями.

| Тип | Сигнатуры |
|---|---|
| `T[]` | `int size()`, `bool isEmpty()`, `T first()`, `T last()`, `bool contains(T)`, `bool isSubsetOf(T[])`, `int indexOf(T)`, `void clear()` |
| `T[]` | `T[] add(T)`, `T[] add(int, T)`, `T get(int)`, `void set(int, T)`, `void addAll(T[])`, `void addAll(int, T[])` |
| `T[]` | `T removeAt(int)`, `bool remove(T)`, `T[] removeAll(T)`, `T[] removeAll(T[])`, `T[] operator +(T[])` |
| `T[]` | `T[] sort()`, `T[] reverse()`, `T[] unique()`, `string join()`, `string join(string)` |
| `T[K]` | `int size()`, `bool isEmpty()`, `void clear()`, `T get(K)`, `T add(K,T)`, `void add(T[K])`, `T remove(K)` |
| `T[K]` | `bool containsKey(K)`, `bool containsValue(T)`, `K[] keys()`, `T[] values()`, `T[K] operator +(T[K])` |

### Поведение текущего runtime

`RCollection` наследует `ArrayList`: порядок и нумерация элементов основаны на нём. `first()` и `last()` возвращают `null` для пустой коллекции. `add` возвращает тот же объект; `sort` и `reverse` изменяют его и возвращают; `unique` создаёт новую коллекцию с порядком первого вхождения; `isSubsetOf` проверяет включение всех элементов текущей коллекции в аргумент. `indexOf` возвращает индекс Java `List.indexOf`, в том числе `-1` при отсутствии. `removeAll(T)` вызывает удаление одного элемента, а перегрузка с коллекцией в данной реализации вызывает `remove(elements)`: не следует приписывать ей массовое вычитание без проверки. `join` преобразует элементы по ветвям реализации, с указанным разделителем или пустой строкой.

Несмотря на название, `RLinkedHashMap` наследует `HashMap`: порядок обхода ключей и значений не гарантируется именем класса. `add(key,value)` вызывает `put` и возвращает предыдущее значение; `get` и `remove` возвращают `null` при отсутствии ключа. Объединение `+` создаёт новое отображение; при совпадающем ключе последующее значение заменяет предыдущее. Порядок вычисления выражений ключей и значений и другие побочные эффекты необходимо проверять отдельно на сгенерированном Java-коде.

## 9.4 Граница фреймворка

`org.zenframework.z8.base` содержит объявления таблиц, полей, запросов, форм, JSON, безопасности, ввода-вывода и т. д. Их атрибуты и методы являются API конкретного фреймворка, а не встроенными грамматическими категориями. Каталог файлов представлен в [приложении](11-library-catalog.md); поведение каждого метода при ошибках, работе с БД, привилегиях и параллельном исполнении должно выводиться из соответствующей реализации, а не из имени или сигнатуры.
