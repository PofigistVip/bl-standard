# 7. Атрибуты, вложенные объекты и Z8

Источники: `C/grammar/Grammar.y`; `C/java/org/zenframework/z8/compiler/parser/{Attribute,LanguageElement}.java`, `parser/type/{AbstractType,DeclaratorNestedType,MemberNestedType}.java`, `parser/type/members/{Member,Records,Record}.java`, `workspace/{StartupCodeLines,StartupCodeGenerator}.java`; `L/org/zenframework/z8/lang/Object.bl` и примеры в `L/org/zenframework/z8/`.

## 7.1 Синтаксис и проверка атрибутов

Атрибут задаётся как `[имя]`, `[имя константа]` или `[имя выражение]` и входит в список модификаторов. Грамматическое принятие выражения не гарантирует его пригодности: `Attribute.validateValue` и `checkSemantics` применяют ограничения к контексту и типу. У объявления поля атрибуты разрешены только для ссылочного типа; у записей `records` действуют отдельные ветви обработки. Пустой атрибут генерируется как пустая строка; значение другого атрибута может вычисляться в контексте связанного объекта.

Известные имена `IAttribute`: `name`, `displayName`, `abstract`, `primary`, `native`, `generatable`, `executable`, `request`, `activator`, `entry`, `job`, `log`. Это имена атрибутов, а не ключевые слова. Компилятор также может передавать другие имена runtime; список не объявляется закрытым.

| Атрибут | Подтверждённое применение |
|---|---|
| `native`, `primary` | для них требуется значение-константа; связь с Java-типом используется при определении native/primary-типа и Java-имени |
| `abstract` | наличие проверяется `AbstractType.isAbstract`; это не ключевое слово объявления класса |
| `name` | проверяются константность, отсутствие ссылки на ресурс и допустимость символов и максимальную длину 128 символов; есть проверки конфликтов |
| `job` | при значении-константе требуется строка; непустая строка проверяется регулярным выражением для пяти полей CRON; `DateToken.checkCron` проверяет форму, но не числовые границы полей |
| `request` | значение-константа должно быть булевым |
| `generatable`, `executable`, `request`, `entry`, `job`, `log`, `name` | участвуют в построении списка регистраций startup через `StartupCodeLines` |
| `displayName`, `activator` | имена известны компилятору; полный контракт потребителей требует исследования runtime |

`[native "полное.Java.Имя"]` связывает BL-объявление с Java-реализацией. `primary` также маркирует тип и задаёт соответствующий Java-тип. Имя атрибута и форма его значения не означают, что любая Java-сигнатура автоматически доступна из BL: методы объявляются в BL.

## 7.2 Вложенная специализация и контейнер

В инициализаторе `T member = class { ... };` тело создаёт вложенную специализацию типа члена. Локальная переменная с такой инициализацией представлена `DeclaratorNestedType`: её базовый тип должен быть ссылочным, компилятор создаёт вложенный Java-класс, экземпляр и массив захваченных локальных переменных. Для специализации существующего поля `MemberNestedType` разрешает имя в контексте объявляющего типа, запрещает массив и enum, повторное определение вложенного типа и статический контекст имени. При создании локальной специализации `DeclaratorNestedType` записывает в closure текущие значения видимых локальных переменных. В проверенном примере последующее переприсваивание `int x` не меняет ранее захваченное значение: метод вложенного объекта видит старое значение. Если захвачена переменная массива, её текущее значение — ссылка на коллекцию, поэтому изменение той же коллекции через `set` видно из вложенного объекта. Проверены `closure captured value` и `closure shared array`; см. `DeclaratorNestedType.initClosure/getCode`, `QualifiedName.getClosureCode`.

Пример из `L/org/zenframework/z8/justintime/table/Source.bl`:

```bl
public Source parent = class {
    virtual protected void beforeRead() {
        super.beforeRead();
        addWhere(isPackage);
    }
};
parentId = parent;
```

`container` внутри вложенного контекста обращается к содержащему объекту; каждый следующий `container` поднимается на один уровень. Это фреймворковая связь, не синоним `super`. Допустимость проверяется статически.

## 7.3 Инициализация и жизненный цикл

Генерация Z8 различает класс, его `CLASS`-представление и объект runtime; Java-тип ссылки компилятор формирует через `T.CLASS<...>`, тогда как primary и enum используют свои Java-типы. `Object.bl` объявляет `virtual protected void constructor()` и метаданные, включая `getAttribute`/`setAttribute`, имя, id, и `auto Object[] objects`. Нельзя считать `constructor()` обычным Java-конструктором BL или обобщать порядок его вызова без проверки стадий создания runtime.

Инициализаторы членов, атрибуты, вложенные специализации, `records` и генерируемые списки регистрации взаимодействуют с runtime и framework. Например, `records` формируют `initStaticRecords`; `StartupCodeLines` строит строки регистрации таблиц, заданий и запросов по атрибутам. Реальные свойства таблиц, SQL, UI, прав доступа и транзакций определяются соответствующими библиотечными классами и реализацией сервера, а не только грамматикой BL.

## 7.4 Наблюдаемая последовательность стадий runtime

Источники: `S/org/zenframework/z8/server/runtime/IClass.java`, `CLASS.java`; `C/java/org/zenframework/z8/compiler/parser/type/members/{TypeBody,Member,MemberInit}.java`. Ниже описан путь через `CLASS.get(stage)` для обычных сгенерированных ссылочных типов; отдельные native-типы могут добавлять собственное поведение.

1. Начальная стадия `Constructor = -1`. При запросе объекта `CLASS.get(stage)` сначала доводит содержащий объект до запрошенной стадии, если требуется; затем при отсутствии объекта вызывает `newObject(container)` и связывает объект с `CLASS`.
2. При переходе на `Constructor1 = 0` runtime устанавливает стадию до вызовов `object.constructor1()` и `object.initMembers()`. Генерируемый `constructor1` собирает и упорядочивает ссылочные инициализаторы с учётом зависимостей имён; `initMembers` сначала вызывает реализацию базового типа, затем добавляет совместимые поля в `auto`-массивы.
3. При переходе на `Constructor2 = 1` runtime устанавливает стадию и вызывает `object.constructor2()`, затем пользовательский `object.constructor()`. Генерируемый `constructor2` сначала вызывает одноимённый метод базового типа, затем вторую фазу членов и атрибутов текущего тела.
4. `CLASS.get()` запрашивает `Constructor2`; если объект уже существует и достиг стадии, повторная инициализация этим обращением не запускается.

Сгенерированный Java-конструктор вызывает `super(container)` и код начального создания членов. `MemberInit` помещает обычное присваивание ссылочного типа в первую фазу, а остальные инициализации и атрибуты — во вторую. Точный порядок независимых ссылочных инициализаторов задаётся `TypeBody.arrangeReferences`; простое текстовое расположение не следует считать полной моделью зависимостей.

Для `auto T[]` генератор `initAutoArrays` рассматривает члены объявляющего типа и добавляет те, чей тип может быть приведён к `T` без оператора преобразования. Полные последствия наследования, повторных обращений, циклов зависимостей и native-расширений требуют отдельных тестов.
