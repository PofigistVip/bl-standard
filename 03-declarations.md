# 3. Единицы компиляции и объявления

Источники: `C/grammar/Grammar.y`, `C/java/org/zenframework/z8/compiler/workspace/CompilationUnit.java`, `parser/type/Type.java`, `Enum.java`, `ImportBlock.java`, `parser/type/members/{Member,AbstractMethod,Record,Records}.java`, `parser/type/{DeclaratorNestedType,MemberNestedType}.java`.

## 3.1 Файл, имя и импорт

Исходный путь относительно корня исходников определяет пакет и полное имя: путь без расширения `.bl` преобразуется заменой разделителей на точки. Объявление `package` в грамматике отсутствует, слово зарезервировано. Импорты идут перед объявлениями и имеют форму `import квалифицированное.имя;`; групповые `*` в BL-грамматике не предусмотрены. Для имени верхнеуровневого класса или enum семантическая проверка требует совпадения с именем файла без расширения. Грамматика допускает последовательность объявлений, но не следует делать из этого вывод о поддержке нескольких независимых типов в файле: `CompilationUnit` хранит один основной `type`.

Для неквалифицированного имени `CompilationUnit.resolveToCompilationUnit` сначала ищет специальные имена в `Primary`, затем явный импорт, затем файл с таким именем в текущей папке. Поиск выполняется в текущем проекте и, при неудаче, в проектах-зависимостях в порядке, задаваемом workspace. Квалифицированное имя преобразуется непосредственно в путь `.bl`. Конфликт импортов и неразрешённый импорт диагностируются.

Пример из `L/org/zenframework/z8/utils/Sorter.bl`:

```bl
import org.zenframework.z8.lang.Object;
[native "org.zenframework.z8.server.utils.Sorter"]
public class Sorter extends Object {
    public void sort(Object[] array);
    virtual public int compare(Object o1, Object o2);
}
```

Это native-объявление; точка с запятой вместо тела допустима вследствие связи с native-типом.

## 3.2 Классы и наследование

Обзор синтаксиса: `{модификатор} ["final"] "class" имя ["extends" квалифицированное-имя] "{" {член} "}"`. `final` стоит непосредственно перед `class`, тогда как остальные модификаторы предшествуют этому заголовку. Указан не более чем один непосредственный базовый тип. Цикл наследования, наследование от enum и наследование от `final`-класса диагностируются. При отсутствии `extends` семантическое дерево не получает явно указанного базового BL-типа, но `Type.getCode` генерирует Java-класс с базой `org.zenframework.z8.server.runtime.OBJECT`; это не доказывает, что BL-поиск членов и преобразования считают класс подтипом библиотечного `Object`.

Содержимое класса может включать объявление поля, инициализацию существующего квалифицированного имени, метод, оператор и блок `records`. Элементы вида `field.subfield = expression;` — часть тела класса, а не только операторы метода. Начальное значение может быть выражением, инициализатором коллекции либо безымянным телом `class { ... }`. Связанные с полем вложенные типы и инициализация рассматриваются в [разделе 7](07-framework.md).

### 3.2.1 Разбор модификаторов

`Parser.Modifiers` отдельно хранит `static`, `auto`, `virtual`, один из `public`/`protected`/`private` и набор атрибутов. Повтор одного модификатора или сочетание двух разных модификаторов доступа вызывает синтаксическую диагностику; повтор атрибута с тем же именем — отдельную диагностику. Порядок обычных модификаторов допускает грамматика, но их комбинации затем проверяются по виду элемента.

| Элемент | Непосредственные проверки `Parser.applyModifiers` |
|---|---|
| поле `Member` | сохраняются доступ, `static`, `auto`; `virtual` диагностируется |
| метод и оператор | сохраняются доступ, `static`, `virtual`; сочетание `static virtual` и `auto` диагностируются |
| инициализация существующего члена `MemberInit` или его вложенная специализация `MemberNestedType` | модификаторы доступа, `static`, `auto`, `virtual` диагностируются |
| запись внутри `records` | сохраняется доступ; `static`, `auto`, `virtual` диагностируются; сама запись представляет статический элемент |
| класс и enum | атрибуты устанавливаются общим кодом; перечисленные выше ветви не доказывают применения прочих модификаторов к типу |

За этой таблицей следуют дополнительные проверки типа, вложенности и значения атрибутов; она описывает точку применения модификаторов, а не разрешает произвольные программы. Для записи `Record.isPublic()` наличие `public` проверяется явно, в отличие от полей и методов с доступом по умолчанию.

## 3.3 Enum

`{модификатор} enum Имя { [Элемент {, Элемент} [,]] }` содержит имена элементов; допускаются пустое тело и завершающая запятая. Из-за рекурсивной продукции `enumMembers` парсер также принимает повторные запятые после элемента, в том числе `enum E { A,, B }`; это подтверждено BL-компиляцией теста и является особенностью реализации, а не рекомендацией стиля. Явные значения или методы внутри этой продукции не предусмотрены. Имя типа проверяется по имени файла. Разрешённость модификаторов и поведение конкретного native enum определяются семантикой и Java-реализацией.

Пример из `L/org/zenframework/z8/base/table/SortDirection.bl`:

```bl
[native "org.zenframework.z8.server.db.sql.SortDirection"]
public enum SortDirection { Asc, Desc }
```

## 3.4 Поля, локальные переменные, параметры

Форма объявления `тип имя` или `final тип имя`, с необязательным `= инициализатором` для поля/локальной переменной. Один параметр состоит из объявления без инициализатора; параметры разделяются запятыми. Массивность записывается у типа, до имени: `int[] values`. Несколько объявлений через запятую в одной продукции не заданы. Тип и имя локальной переменной разрешаются семантически; повторное объявление видимой локальной переменной диагностируется.

Поля с одинаковым именем, включая конфликт с унаследованным полем, диагностируются. `static` запрещён для ссылочного поля и массива, содержащего ссылочные типы, а также внутри вложенного типа. Атрибуты поля разрешаются только для ссылочного типа. `auto` у члена разрешён только для одномерного неассоциативного массива не-primary-типа. `Declarator.isFinal()` хранит признак `final` локального декларатора; `Member.isFinal()` в исследованном коде возвращает `false`. Контрольные BL-программы с повторным присваиванием и `final`-локальной переменной, и `final`-полю приняты компилятором; компиляция полученной Java и выполнение отдельно не проверялись. Правила неизменяемости нельзя выводить из одного наличия токена: см. `Initialization`, `Assignment`, `Declarator`.

Для поля и метода отсутствие модификатора доступа рассматривается их `isPublic()` как `public`. `private` у проверок доступен объявляющему типу и содержащимся в нём типам; `protected` учитывает подтипы и цепочку содержащих типов (`AbstractType.hasPrivateAccess/hasProtectedAccess`). Конкретные проверки квалифицированного доступа выполняются в `QualifiedName` и `MethodCall` и могут зависеть от контекста.

### 3.4.1 Проверенная матрица доступа

Для члена `Value`, используемого в `SpecProbe`, BL-компилятор дал следующие результаты как для поля, так и для метода. Проверка «другой класс» использует получателя `Value`, а «подкласс» — унаследованное имя; эти 16 случаев запускаются `tests/compile_probes.py`.

| Модификатор члена | Другой класс в том же пакете | Подкласс |
|---|---|---|
| отсутствует | принят | принят |
| `public` | принят | принят |
| `protected` | ошибка видимости | принят |
| `private` | ошибка видимости | ошибка видимости |

Этот результат соответствует `Member.isPublic`, `AbstractMethod.isPublic`, `QualifiedName` и `MethodCall`; дополнительно вложенный контекст обрабатывается через `hasPrivateAccess`/`hasProtectedAccess`. Проверка защищённого доступа не равнозначна правилу «один пакет даёт доступ».

Для верхнеуровневого класса компилятор принял и позволил использовать из другого пакета каждую из форм `private class`, `protected class`, `public class`, `static class`, `auto class`, `virtual class`; во всех шести тестах генератор вывел Java `public class`. В `Parser.applyModifiers` для `Type` нет ветви, сохраняющей эти токены. Это наблюдаемая особенность текущей реализации; `final` обрабатывается отдельно и запрещает наследование. Проверялись BL-компиляция и текст Java, но не исполнение этих шести классов.

### 3.4.2 Области видимости и разрешение имён

Параметры метода и локальные переменные учитываются в стеке областей `AbstractMethod.localScopes`. Блок, обычный `for`, `for-each` и `catch` открывают и закрывают соответствующие области; параметры добавляются в область тела метода. `findLocalVariable` ищет от ближайшей области к внешним. При объявлении локальной переменной компилятор проверяет все активные области метода: нельзя повторно объявить имя видимого параметра или локальной переменной даже во вложенном блоке. После выхода из области её имена больше не участвуют в этом поиске. Это подтверждено проверками `nested local redefinition` и `parameter redefinition` в [тестах компилятора](tests/compile_probes.py).

При поиске первого компонента неуточнённого имени `QualifiedName` рассматривает локальную переменную текущего метода, затем член объявляющего типа, затем при определённых условиях захваченную переменную внешнего метода и разрешённое имя типа. Поэтому локальная переменная может скрывать поле: тест `local shadows field` принят. При последующих компонентах ищется член типа текущего результата с отдельной проверкой `static` и видимости. Алгоритм и порядок конкретных ветвей — в `parser/expressions/QualifiedName.java`, `parser/statements/Declarator.java`, `type/members/AbstractMethod.java`; это не общий механизм пространств имён Java.

## 3.5 Методы и операторы

Заголовок метода `тип имя(параметры)` сопровождается телом `{ ... }` либо `;`. Согласно `AbstractMethod.resolveTypes`, отсутствие тела допускается только для native-типа. Перегрузки различаются сигнатурами; повтор метода в типе диагностируется. При переопределении соответствующей сигнатуры тип результата должен совпадать, статичность должна быть совместима, а нестатический унаследованный метод должен быть `virtual`. Переопределённый виртуальный метод остаётся виртуальным. Вложенный тип не может объявлять `static`-метод.

Операторы объявляются как `тип operator знак(параметры)`; грамматика перечисляет `! ~ * / % + - == != < > <= >= & | ^ && || =`. Проверка `Operator.resolveStructure` ограничивает число параметров максимум одним. `operator Тип()` — оператор преобразования без параметров. `operator()` — специальный priority-оператор без параметров; его тип результата — объявляющий тип. Семантика выбора описана в [разделе 5](05-expressions.md).

## 3.6 Records

`records { { {модификатор} имя = константа; } }` объявляет статические константы записей. Хотя грамматика принимает любой токен `Constant`, `Record.resolveStructure` требует именно GUID и запрещает конфликт имён. Генератор создаёт статические члены и код `initStaticRecords`, вызывающий инициализацию базового типа и регистрирующий записи.

Пример из `L/org/zenframework/z8/base/table/system/Roles.bl`:

```bl
records {
    [name "Администраторы"]
    Administrator = 'DC08CA72-C668-412F-91B7-022F1C82AC09';
}
```
