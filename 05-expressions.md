# 5. Выражения и операции

Источники: `C/grammar/Grammar.y`; `C/java/org/zenframework/z8/compiler/parser/expressions/`; `parser/type/members/{Operator,PriorityOperator,CastOperator}.java`; `L/org/zenframework/z8/lang/*.bl`.

## 5.1 Приоритет и группировка

Таблица следует иерархии продукций `Grammar.y`, от более сильной к более слабой. Точное разрешение неоднозначностей определяется yacc-грамматикой и сгенерированным parser; не все операции являются свободно цепляемыми.

| Уровень | Форма | Группировка по продукции |
|---|---|---|
| первичные/постфиксные | литерал, имя, `this`, `super`, `container`, скобки, вызов, `.`, `[]`, `new`, приведение | постфиксные формы могут продолжаться |
| унарные | `+ - ! ~` | рекурсивно справа |
| мультипликативные | `* / %` | слева |
| аддитивные | `+ -` | слева |
| отношения | `< > <= >=` | только одна операция на уровне без дополнительных скобок |
| равенство | `== !=` | только одна операция на уровне без дополнительных скобок |
| побитовое И, XOR, ИЛИ | `&`, `^`, `\|` | каждый уровень слева |
| логическое И, ИЛИ | `&&`, `\|\|` | каждый уровень слева |
| условное | `condition ? a : b`, `a ?: b` | см. продукцию `ternaryExpression` |
| проверка типа | `expression instanceof простойТип` | внешняя продукция expression |
| присваивание | `= += -= *= /= %= &= \|= ^=` | отдельная продукция `assignment`, не обычный уровень `expression` |

Запись `a = b = c` нельзя считать допустимой только по аналогии с Java: правая часть присваивания задаётся `expression`, а не `assignment`. Унарный `+` в грамматике не вызывает `parser.onUnary`; это отличается от `-`, `!`, `~` и требует осторожности при выводах о вызове перегруженного оператора.

## 5.2 Разрешение операций и вызовы

Методы и операторы перегружаются: компилятор разрешает типы получателя и аргументов, проверяет доступность, статический контекст и применимые преобразования; отсутствие кандидата и неоднозначность диагностируются. Реальное действие численных и других операций задаётся объявленным оператором типа и его Java-реализацией. Например, `int.bl` объявляет арифметику с `int` и `decimal`, а `bool.bl` — `!`, `&&`, `||`, `==`, `!=`. Нельзя без отдельной проверки приписывать всем типам одни и те же операторы или универсальное переполнение.

Компилятор отдельно генерирует для `bool && bool` и `bool || bool` условный Java-код с коротким замыканием: правый операнд вычисляется только при необходимости. Для других применимых перегрузок правила вычисления выводятся из `BinaryExpression.getCode` и реализации оператора; не следует автоматически обобщать короткое замыкание.

`this` и `super` обозначают текущий контекст объекта и контекст базового типа; их допустимость определяется семантическим анализом. `container` и повторное `container.container` переходят по содержащим типам, запрещены при отсутствии нужного контейнера и в статическом контексте. Доступ — через `.`; вызов имеет вид `имя(аргументы)` или `получатель.имя(аргументы)`. Аргументы могут включать литеральные инициализаторы коллекции с ожидаемым типом.

### 5.2.1 Наблюдаемый алгоритм бинарного оператора

`BinaryExpression.checkSemantics` сначала рассматривает операторы с одним параметром у левого типа и совместимое преобразование правого аргумента. При одном лучшем кандидате он используется; несколько одинаково подходящих приводят к диагностике. Если прямого кандидата нет, компилятор рассматривает операторы преобразования левого типа и ищет операцию у результатов этих преобразований. Ноль вариантов — неопределённая операция, больше одного — неоднозначность. Это асимметричный поиск: нельзя предполагать автоматическую перестановку операндов.

Если любой операнд имеет специальный тип `null`, проверка в `BinaryExpression` возвращает успех до обычного поиска операции, а генерация вставляет знак между Java `null` и другим операндом и оборачивает результат в `bool`. Это особенность backend: принятие компилятором само по себе не гарантирует, что любой такой знак образует допустимую Java-операцию или что вызов безопасен. Для enum генератор также имеет отдельную ветвь сравнения. Правила перегрузки отдельных унарных операций реализованы в `UnaryExpression`.

## 5.3 Создание, проверка типа и выбор

Грамматическая форма создания — `new Identifier`, без обязательных скобок и аргументов. `OperatorNew` разрешает этот тип и генерирует создание через `VariableType.getJavaNew`; наличие Java-конструктора с аргументами нельзя предполагать по аналогии с Java.

Для `условие ? a : b` условие приводится к `bool`. Компилятор сначала пытается преобразовать тип `a` в тип `b`; при успехе выбирается тип `b`, иначе пытается преобразовать `b` в `a`. Если оба направления недоступны, выдаётся ошибка. На этапе исполнения вычисляется выбранная ветвь.

`a ?: b` возвращает `a`, если результат `a` не равен `null`, иначе вычисляет и возвращает `b`; `a` вычисляется один раз во временную переменную. Результат имеет тип `a`; `b` должен приводиться к нему. Речь о проверке null, не о проверке пустой строки, нуля или `false`.

`x instanceof T` задаётся с простым типом, не массивной продукцией `type`. Доступность и результат зависят от проверок `InstanceOf.java` и представления объектов runtime.

## 5.4 Присваивание

Левая часть должна представлять переменную/допустимое левое значение. Присваивание проверяет совместимость и может использовать `operator =`; составные присваивания переводятся через соответствующий оператор и присваивание. В теле класса `qualifiedNameInit` отдельно поддерживает простую форму, `=` и `+=`. Не предполагается общая гарантия единственного вычисления сложного левого операнда: для неё нужна проверка генератора и тест.
