# 4. Типы, преобразования и коллекции

Источники: `C/java/org/zenframework/z8/compiler/parser/{variable/VariableType,variable/NullVariableType,type/Primary,type/TypeCast,type/TypeCastSet,type/members/ArrayMethods}.java`, `parser/expressions/{ArrayInitializer,MapElement,ArrayAccess,TypeCastExpression}.java`, `L/org/zenframework/z8/lang/` и `S/org/zenframework/z8/server/runtime/{RCollection,RLinkedHashMap}.java`.

## 4.1 Модель типа

Тип переменной — квалифицированное имя типа с нулём или более измерениями. `T[]` обозначает последовательность `T`; `T[K]` — отображение ключей `K` в `T`; измерения могут сочетаться. Правая скобочная пара — внешнее измерение при индексировании, поскольку `ArrayAccess` берёт `getRightKey()`. В контексте типа содержимое непустых скобок семантически разрешается как единственный идентификатор типа ключа (не квалифицированное имя); грамматика использует общую продукцию индекса, поэтому произвольное выражение в скобках не следует считать корректным типом ключа.

Примеры форм (схематические): `int[]`, `string[guid]`, `int[][string]`. Пустые скобки в выражении инициализации не следует смешивать с индексированием существующего значения. Массивы и отображения — один класс типов с разным ключом измерения. Это коллекции runtime, не Java-массивы фиксированной длины.

## 4.2 Имена специальных типов

`Primary.nameToPath` определяет предустановленное разрешение `void`, `primary`, `binary`, `bool`, `date`, `datespan`, `decimal`, `exception`, `file`, `geometry`, `guid`, `int`, `string`, `vector`, `bitset`; SQL-имена `sql_binary`, `sql_bool`, `sql_date`, `sql_datespan`, `sql_decimal`, `sql_geometry`, `sql_guid`, `sql_int`, `sql_string`, `sql_vector`, `sql_bitset`. Наличие записи в таблице имён не гарантирует существования файла или доступности типа в данном проекте: в исследованном `L` файлов для `vector`, `bitset` и их SQL-аналогов нет. Полный перечень фактически имеющихся объявлений и их API — в [разделе 9](09-library.md).

В частности, `int`, `bool`, `decimal`, `string`, `date`, `datespan`, `guid`, `binary` имеют библиотечные объявления и Java-реализации; не считайте их машинными примитивами Java. `void` используется как тип отсутствующего результата. `Object` — тип фреймворка, не отдельное ключевое слово. Тип `null` представлен `NullVariableType`, а не обычным объявлением `.bl`.

## 4.3 Совместимость и преобразования

Тождественные типы совместимы. Для обычных типов компилятор ищет путь к базовому типу и применимые объявленные операторы преобразования. `TypeCast` предпочитает обычный путь наследования оператору преобразования и для сравнения отдельных преобразований использует расстояние до базового типа. В `TypeCastSet`, применяемом к наборам аргументов, вес является суммой штрафов за преобразования оператором (по 100); равные веса считаются неоднозначными. Нельзя заменять этот алгоритм Java-правилами перегрузки.

Для коллекций `VariableType.getCastTo` требует одинакового числа измерений, совместимости базового типа по наследованию и попарной совместимости ключей: оба пустые либо оба непустые и совместимые по наследованию. Это проверка компилятора; гарантий безопасности мутаций коллекций она сама по себе не устанавливает.

Явное преобразование `(T) значение` сначала ищет обычное преобразование значения в `T`; при отсутствии допускает обратную связь наследования и генерирует downcast. Несовместимые типы диагностируются. В библиотеке, например, `int` объявляет `operator decimal()` и `operator string()`.

`NullVariableType.getCastTo` возвращает преобразование к кандидатному типу, однако дальнейшая пригодность зависит от контекста, выбранной операции и сгенерированного Java-кода. Контрольный BL-метод типа `int` с `return null;` принят BL-компилятором, но сгенерированная Java не компилировалась и не исполнялась. Не делается глобального утверждения, что `null` корректно и безопасно в каждом контексте каждого типа.

## 4.4 Инициализация и индексирование

Инициализатор `{}` или `{a, b, ...}` требует ожидаемого типа коллекции; для отображения элементы имеют форму `(ключ, значение)`, например схематически `string[guid] names = { ('00000000-0000-0000-0000-000000000000', "нет") };`. Допускаются вложенные инициализаторы и завершающая запятая. `T[] { ... }` задаёт типизированный инициализатор в выражении. Тип каждого элемента проверяется по ожидаемому типу; ключ массива/карты сам не должен быть массивом. Точная семантика повторных ключей и отсутствующего ключа зависит от runtime.

При `a[index]` выражение должно иметь тип коллекции. Индекс пустого измерения приводится к `int`, индекс карты — к объявленному типу ключа; результат имеет тип с удалённым правым измерением. Генератор обращения вызывает `.get(index)`. Методы последовательности и карты приведены в [разделе 9](09-library.md).
