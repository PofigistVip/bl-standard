# 6. Операторы и управление потоком

Источники: `C/grammar/Grammar.y`; `C/java/org/zenframework/z8/compiler/parser/statements/`; `parser/expressions/Assignment.java`; `parser/type/members/AbstractMethod.java`.

## 6.1 Блоки и локальные объявления

Блок `{ ... }` содержит ноль или более операторов и задаёт локальную область видимости. Декларатор и выражение/присваивание в обычной позиции завершаются `;`. Грамматика содержит специальные продукции восстановления при пропущенных разделителях; они не делают ошибочные программы корректными. Семантика выявляет повторные локальные имена и недостижимый код после завершающих управление операторов.

## 6.2 Ветвление

`if (выражение) оператор [else оператор]`. Условие проверяется на преобразование к `bool`; в реализации условие используется для выбора одной из ветвей. Скобки в этом пункте обозначают буквальные символы BL. Для вложенного `if` без фигурных скобок следует учитывать разрешение неоднозначности parser; используйте блоки для явного связывания `else`.

## 6.3 Циклы

| Форма | Синтаксис | Существенные ограничения |
|---|---|---|
| while | `while (условие) оператор` | условие преобразуется к `bool` |
| do | `do оператор while (условие);` | условие после тела |
| for | `for ([начало]; условие; шаг) оператор` | по грамматике начало может отсутствовать, но условие и шаг обязательны; шаг — `assignment` |
| for-each | `for (тип имя : выражение) оператор` | проверяется тип массива и совместимость элемента с переменной |

`for(;;)` и Java-формы с отсутствующим условием/шагом не следуют из данной грамматики. Для `for-each` `ForEachStatement` проверяет приведение коллекции к массиву переменной цикла; наличие внешнего измерения карты не следует автоматически считать поддержкой обхода карты. Начальная переменная цикла имеет локальную область.

## 6.4 Переходы и возвращение

`break;` и `continue;` допустимы только внутри цикла. `return;` используется без результата, `return выражение;` и `return {инициализатор};` — с результатом. `void`-метод не должен возвращать значение, а для метода с результатом проверяются наличие результата и преобразование к объявленному типу. Компилятор также проверяет, что метод с результатом возвращает его на всех путях согласно собственному анализу `returnsOnAllControlPaths`; циклы не считаются гарантирующими возврат только потому, что человек считает их бесконечными.

## 6.5 Исключения

`throw выражение;` требует тип, приводимый к библиотечному `exception`. Конструкция `try { ... }` должна иметь минимум один `catch (тип имя) { ... }` или `finally { ... }`; возможны несколько `catch` и заключительный `finally`. Тип параметра catch проверяется относительно `exception`. Генератор выводит Java `try`, последовательные `catch` и `finally`. Повтор одинакового типа catch диагностируется. Для primary-типа catch генератор перехватывает `java.lang.Throwable` и создаёт BL-исключение из сообщения и исходного исключения; последующий catch после такого обработчика отмечается как недостижимый при анализе возвратов. Для других типов генерируется Java `catch` с соответствующим типом. Конкретные исключения библиотечных операций здесь не объявляются универсальными.
